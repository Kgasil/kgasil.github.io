Do problema à arquitetura.

Sete estudos de caso que documentam a lógica de negócio, os componentes técnicos e as limitações de projetos independentes. Os fluxos são esquemas conceituais, não capturas de sistemas em produção. As evidências são descritas nos repositórios; não reivindico resultados empresariais ou testes executados nesta revisão.

Inteligência de manutenção

Desafio de negócio

Sem histórico estruturado de falhas, fica difícil priorizar ativos e avaliar a manutenção corretiva.

Abordagem técnica

Modelar ativos e ordens de serviço; higienizar códigos, remover duplicidades e cruzar os registros com o cadastro de ativos.

Arquitetura conceitual

Ativos e ordens
→
SQL / limpeza Python
→
Indicadores
→
Consumo BI

Evidências documentadas

O repositório contém analise_manutencao.sql, limpeza_e_cruzamento.py e testes de limpeza. As consultas consolidam downtime, custos, MTTR estimado e mix de manutenção.

Comando ou função de referência

python -m unittest -v test_limpeza

Escopo e limitações

As amostras SQL e Python são fictícias e distintas. Não há PBIX nem cálculo de MTBF; o MTTR usa horas de parada corretiva.

Governança cadastral

Desafio de negócio

Consultas manuais de CNPJ podem introduzir divergências de formato e retrabalho em bases cadastrais.

Abordagem técnica

Normalizar a entrada como texto, verificar 14 dígitos, consultar uma fonte primária com fallback e registrar o status da sincronização.

Arquitetura conceitual

Google Sheets
→
Normalização
→
BrasilAPI / fallback
→
Registro de status

Evidências documentadas

Codigo.gs documenta a execução em lote com BrasilAPI, Minha Receita e pausa configurável. A saída inclui dados cadastrais e status.

Comando ou função de referência

enriquecerBaseCNPJs

Escopo e limitações

A validação verifica formato numérico, não dígitos verificadores. A execução depende de autorização e quotas externas. Não use dados de clientes.

03Operações & automaçãoDemonstração operacional

Engenharia de custos e precificação

Desafio de negócio

Orçamentos com categorias inconsistentes e regras de margem pouco claras podem aumentar o risco de subprecificação.

Abordagem técnica

Separar materiais, mão de obra e deslocamento; aplicar markup divisor e verificar uma margem mínima demonstrativa.

Arquitetura conceitual

Insumos
→
Custo direto
→
Markup divisor
→
Revisão de margem

Evidências documentadas

Calculadora_Orcamento.gs consolida custos e estima o preço: custo direto / (1 − impostos − margem-alvo). A regra de revisão usa 18% como parâmetro demonstrativo.

Comando ou função de referência

calcularOrcamentoTecnico

Escopo e limitações

Parâmetros ilustrativos, sem orientação fiscal. A margem estimada não equivale a lucro líquido contábil completo.

Controle de demandas full stack

Desafio de negócio

A falta de uma visão centralizada das solicitações dificulta acompanhar status e estimativas de custo.

Abordagem técnica

Modelar a tabela de demandas, criar endpoints REST para cadastro e atualização e conectar a interface web à persistência SQLite.

Arquitetura conceitual

Interface web
→
Flask REST
→
SQLite
→
Status e relatórios

Evidências documentadas

app.py, index.html e schema_e_consultas.sql demonstram a arquitetura. O repositório documenta testes de criação, atualização de status e entradas inválidas em banco temporário.

Comando ou função de referência

python -m unittest -v test_app

Escopo e limitações

Uso local somente. A documentação aponta renderização insegura de dados via innerHTML; é necessário corrigir isso e adicionar autenticação antes de qualquer exposição pública.

06Operações & desenvolvimentoDemonstração de regras

Decisão operacional baseada em regras

Desafio de negócio

Sem critérios explícitos, equipes podem priorizar solicitações de forma inconsistente.

Abordagem técnica

Encapsular atributos de demandas e calcular pontuação de 0 a 100 considerando criticidade, SLA e faixa de custo.

Arquitetura conceitual

Demanda
→
Validação
→
Score 0–100
→
Prioridade / revisão

Evidências documentadas

GestaoPrioridadeApp.java executa três solicitações fictícias e apresenta classificação de urgência e avaliação de aprovação. A estrutura usa POO e regras de negócio.

Comando ou função de referência

javac -encoding UTF-8 GestaoPrioridadeApp.java && java GestaoPrioridadeApp

Escopo e limitações

As regras são ilustrativas; não representam política de aprovação empresarial em produção.

07IA aplicadaProtótipo de aprendizado guiado

Integração de IA em uma interface de aprendizado

Desafio de negócio

Compreender na prática como uma interface envia mensagens a um modelo de linguagem e apresenta respostas.

Abordagem técnica

Personalizar um exercício guiado, organizar o prompt e estado de sessão em Streamlit e conectar a API Groq.

Arquitetura conceitual

Pergunta
→
Streamlit / sessão
→
Groq API / LLM
→
Resposta

Evidências documentadas

O repositório contém code.py, dependências e documentação. A interface local original foi demonstrada; a implementação pública é separada e assistida por IA. O exercício original é creditado à Data Science Academy.

Comando ou função de referência

streamlit run code.py

Escopo e limitações

A implementação pública não foi verificada ponta a ponta e não possui testes automatizados documentados. Respostas de IA precisam de revisão; nunca publique chaves de API.
